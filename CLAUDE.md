# CLAUDE.md

Этот файл даёт Claude Code контекст о проекте при работе в этой директории.

## Что это за проект

Локальный монитор объявлений Avito. Периодически открывает страницу
поиска Avito через Playwright, парсит карточки объявлений, сравнивает
их с локальной SQLite-базой и уведомляет о новых объявлениях и
изменении цены (в консоль и опционально в Telegram).

Не веб-сервис, не деплоится — запускается вручную или по расписанию
(cron / Task Scheduler) на машине пользователя.

## Структура

- `config.py` — все настраиваемые параметры (URL поиска, интервалы,
  задержки, Telegram). Единственный файл, который обычно правит
  пользователь, а не Claude.
- `scraper.py` — вся логика Playwright: открытие страницы, парсинг
  карточек по `data-marker`-атрибутам, загрузка полного описания.
- `db.py` — тонкая обёртка над `sqlite3`: таблица `listings`,
  функции `get_listing` / `upsert_new` / `update_price` / `touch`.
- `notify.py` — вывод уведомлений (консоль + опционально Telegram Bot API).
- `main.py` — точка входа, цикл проверки (`process_items` сравнивает
  свежие данные с базой и решает, что это — новое объявление,
  изменение цены или ничего не изменилось).
- `requirements.txt` — `playwright`, `requests`, `anthropic`, Flask.
- `README.md` — инструкция по установке и запуску для пользователя.

**Веб-режим (поиск машин с LLM-агентом):**

- `url_builder.py` — конструирование URL поиска Avito по параметрам
  фильтров из веб-формы (город, марка, цена, пробег, год).
- `agent.py` — оценка релевантности объявлений через Claude API
  (Claude Haiku), работает с фильтрами и критериями поиска.
- `worker.py` — фоновый рабочий процесс, периодический парсинг Avito
  и вызов агента для ранжирования, хранение результатов.
- `app.py` — Flask-приложение, HTTP API для фронтенда (список фильтров,
  сохранение поиска, получение результатов).
- `frontend/` — React-приложение, собирается в статику (npm run build),
  заполнение фильтров и вывод результатов.
- `.env.example` — шаблон переменных окружения (ANTHROPIC_API_KEY и др.).

Данные (`avito_monitor.db`) создаются при первом запуске и в репозиторий
не входят.

## Команды

**CLI-режим (мониторинг):**

```bash
pip install -r requirements.txt
playwright install chromium

python main.py --once     # одна проверка, для отладки
python main.py            # непрерывный цикл
```

**Веб-режим (поиск с LLM):**

```bash
pip install -r requirements.txt
playwright install chromium

cp .env.example .env
# впишите в .env свой ANTHROPIC_API_KEY (https://console.anthropic.com/)

cd frontend
npm install
npm run build
cd ..

python app.py             # веб-сервер на http://localhost:5000
```

Тестового окружения/сети в песочнице Claude нет — проверять запуск
нужно локально у пользователя. Если Claude меняет `scraper.py`, стоит
явно попросить пользователя прогнать `python main.py --once` и
прислать вывод/ошибку, а не считать изменения рабочими только по
исходному коду.

## Важные соглашения

- **Все селекторы — через `data-marker`, не через CSS-классы.**
  Классы Avito меняет часто, `data-marker` стабильнее. Если
  добавляется парсинг нового поля — сначала искать подходящий
  `data-marker` в разметке (пользователь должен прислать HTML или
  скриншот DevTools), а не гадать по классам.
- **Не убирать и не уменьшать задержки** (`MIN_DELAY`, `MAX_DELAY`,
  `INTERVAL_JITTER_SEC`) без явной просьбы пользователя — это
  сознательная мера против блокировки по IP.
- **`HEADLESS = False` по умолчанию** — осознанный выбор
  (headless-режим Playwright детектируется чаще). Не менять на
  `True` в коде по умолчанию.
- ID объявления вытаскивается regexp'ом из URL (`_extract_id` в
  `scraper.py`) — если Avito сменит формат ссылок, это первое, что
  нужно поправить.
- Все уведомления/логи — на русском языке, в том же стиле, что уже
  есть в `notify.py` (эмодзи 🆕 / 💰 + короткий текст).
- Веб-режим (`app.py`) использует интервал 60 сек по прямой просьбе
  пользователя — это единственное отступление от «не уменьшать интервалы»,
  остальные задержки (`MIN_DELAY`/`MAX_DELAY`/джиттер) не меняются.
- `ANTHROPIC_API_KEY` — только через `.env`/переменную окружения, никогда
  не хардкодить в `config.py`.
- Не добавлять функциональность для массового скрапинга контактов,
  телефонов или персональных данных третьих лиц без явного запроса —
  это выходит за рамки задачи (личный мониторинг) и упирается в
  152-ФЗ и пользовательское соглашение Avito.

## Типичные доработки, которые могут попросить

- Пагинация (сбор с нескольких страниц выдачи).
- Экспорт истории в CSV/Excel.
- Фильтрация по диапазону цены/ключевым словам до уведомления.
- Запуск как systemd-сервис или задача планировщика Windows.
- Поддержка нескольких поисковых запросов одновременно (сейчас — один
  `SEARCH_URL` в конфиге).

При такой доработке — смотреть, ложится ли она в существующие модули
(`scraper.py` / `db.py` / `notify.py` / `main.py`) без разрастания
одного файла; если логика заметно новая (например, несколько запросов
параллельно), выносить в отдельный модуль, а не пихать в `main.py`.
