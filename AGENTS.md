# AGENTS.md

Правила проекта. Этот файл читает ваш AI-ассистент — Claude Code (через `@AGENTS.md`
в `CLAUDE.md`), Codex, Cursor и другие инструменты, понимающие эту конвенцию.

Файл состоит из двух частей. **Часть I** — правила курса, по которым велась
работа над последней доработкой проекта (см. `sessions/`), они одинаковы для
всех и менять их не нужно. **Часть II** — настройки конкретно этого проекта.

# Часть I. Правила курса

## 1. Как ведётся работа

Шесть правил с первого занятия. Они обязательны — и именно их следы
мы ищем в журнале работы.

**Свой файл правил.** Часть II этого файла заполняете вы, под свою задачу.
Написать черновик может агент, но принимать — вам: прочитайте глазами
и вычеркните то, чего в проекте нет.

**Режим разрешений выбирается осознанно.** Не работайте в режиме, где агент
не спрашивает ничего, только потому, что так меньше кликов. Зафиксируйте
в журнале выбранный режим и почему именно он.

**Сначала описание и план, потом работа.** Прежде чем агент начнёт править файлы,
у вас на руках должны быть записанное описание задачи и план. Их правит человек —
это самая дешёвая точка вмешательства.

**Проверка вместо слова «готово».** Утверждение агента, что всё работает,
доказательством не является. Доказательство — запуск с показанным выводом:
тесты, открытая страница, снимок экрана. В журнале нужны случаи, где агент
сказал «готово», а проверка это опровергла.

**Независимый взгляд.** Хотя бы раз пропустите результат через проверку со стороны:
вторая модель, чистая сессия без истории обсуждения или отдельный агент-ревьюер.
Что нашлось — в журнал.

**Одна задача — одна сессия.** Новая задача начинается в новой сессии.
Если третья попытка починить одно и то же снова не удалась — не продолжайте
в том же диалоге, начните заново с нормальным описанием проблемы.

## 2. Журнал работы

Ход работы фиксируется на диске и сдаётся вместе с решением. Мы оцениваем
не только то, что получилось, но и то, как вы к этому шли. Готовый код
без журнала — неполная сдача.

### Где лежит

В корне проекта — папка `sessions/`. Внутри — файл на каждую сессию работы.
Сессия — это один подход к задаче: сели, поработали, закрыли ноутбук.

```
sessions/
├── STATE.md              # состояние проекта «как есть» (перезаписывается)
├── TOOLS.md               # журнал инструментов (только дополняется)
├── session-1.md
└── session-N.md
```

Код в журнале не дублируется — он лежит там, где ему место. В журнале только то,
чего в коде не видно: что просили, что думали, чем закончилось.

### Файл сессии

Обязательные разделы, в этом порядке: заголовок с датой/ассистентом/режимом
разрешений/статусом, «Промпты» (дословно, без правки опечаток), «Размышления»
(главный раздел — почему А, а не Б, где ассистент ошибся, как это заметили),
«Использованные инструменты», «Изменения в проекте», «Финальный вердикт».

### `TOOLS.md` — журнал инструментов

Только дополняется. Фиксирует всё, что добавлено в проект или окружение ради
задачи: библиотеки, CLI-утилиты, MCP-серверы, плагины и скиллы ассистента.
Тупиковая попытка — тоже запись.

### `STATE.md` — состояние проекта

Обновляется в конце каждой сессии, описывает «как есть сейчас»: что готово,
что в работе, что не начато, известные проблемы, следующий шаг.

## 3. Что мы читаем в журнале

Постановка (замечены ли неоднозначности и как разрешены), выбор (есть ли
отвергнутые варианты), работа с ассистентом (проверяется ли выдача, ловятся
ли ошибки), честность (тупики и откаты повышают доверие к журналу, а не
понижают), границы (понятно ли, что осталось за рамками).

## 4. Чего не делать

Не переписывать журнал задним числом. Не генерировать его одним промптом в
конце. Не коммитить секреты и ключи. Не складывать в журнал код и логи.

# Часть II. Настройки проекта

## Что это за проект

Локальный монитор объявлений Avito. Два независимых режима:

- **CLI** (`main.py`) — периодически открывает страницу поиска Avito через
  Playwright, парсит карточки, сравнивает с локальной SQLite-базой
  (`DB_PATH`) и уведомляет о новых объявлениях/изменении цены (консоль,
  опционально Telegram). Не веб-сервис, не деплоится — запускается вручную
  или по расписанию на машине пользователя.
- **Веб-режим** (`app.py`) — поиск автомобилей с оценкой релевантности через
  Gemini API и React-интерфейсом; своя БД (`WEB_DB_PATH`), не пересекается с
  CLI. Поддерживает **две независимые параллельные поисковые сессии**
  (`session_id ∈ {1, 2}`, `?session=1|2` в URL) — разные фильтры, разные
  результаты, фоновый воркер обслуживает их по очереди в одном потоке (без
  настоящей многопоточности — см. запреты ниже) с кросс-сессионным дедупом
  объявлений на 24 часа. Подробности архитектуры — `CLAUDE.md`; спецификация
  и история разработки этой фичи — `SPEC.md` и `sessions/`.

## Стек и версии

Python 3.11, Playwright + Chromium (скрапинг), SQLite (`sqlite3`, без ORM),
Flask (веб-режим), React + TypeScript + Vite (`frontend/`), Google Gemini API
через `google-genai` (оценка релевантности в веб-режиме), Pydantic
(структурированные ответы агента), `requests` (Telegram-уведомления).
Версии — по `requirements.txt`/`frontend/package.json`. Менять версию
Python/Playwright или уходить с SQLite на другое хранилище — только с
вопросом.

## Как запускать и проверять

```bash
# установка зависимостей
pip install -r requirements.txt
playwright install chromium

# CLI-режим
python main.py --once     # одна проверка, для отладки
python main.py            # непрерывный цикл

# веб-режим
cp .env.example .env      # и вписать GEMINI_API_KEY
cd frontend && npm install && npm run build && cd ..
python app.py             # http://localhost:5050 (WEB_PORT), ?session=1|2

# тесты
python3 -m pytest -v

# линтер и форматирование
# отдельного линтера в проекте нет — не заводить новый без вопроса
```

Тестового окружения/сети в песочнице агента нет — проверять реальный запуск
скрапинга нужно локально у пользователя.

## Что нельзя трогать

Формулировки здесь категоричные — мягкая просьба не работает (см. `CLAUDE.md`
и `sessions/` про режим `bypass permissions`, в котором это особенно важно).

- Ни при каких обстоятельствах не увеличивать частоту запросов к Avito —
  не менять `MIN_DELAY`, `MAX_DELAY`, `CHECK_INTERVAL_SEC`,
  `INTERVAL_JITTER_SEC` в `config.py`.
- Ни при каких обстоятельствах не делать настоящую многопоточность или
  несколько параллельных браузеров для скрапинга Avito — веб-режим
  чередует свои две сессии строго последовательно, в одном потоке.
- Ни при каких обстоятельствах не менять `HEADLESS` на `True` по умолчанию.
- Ни при каких обстоятельствах не подключать прокси или смену IP.
- Не коммитить `.env`, ключи API, файлы `avito_monitor*.db`.
- Селекторы Avito — только через `data-marker`, никогда через CSS-классы.
- Не удалять и не пересоздавать существующие пользовательские данные —
  изменения схемы БД только через миграцию (пересборка таблицы в явной
  транзакции для изменений PRIMARY KEY/CHECK, простой `ALTER TABLE ADD
  COLUMN` для остального — см. `db.py`), никогда через удаление файла БД.
- Не менять порт веб-интерфейса на 5000 по умолчанию (`WEB_PORT`,
  сейчас 5050) — на macOS порт 5000 занят AirPlay Receiver.
- Не добавлять функциональность для массового скрапинга контактов,
  телефонов или персональных данных третьих лиц без явного запроса.

## Когда агент обязан остановиться и спросить

- Если для реализации нужно менять тайминги скрапинга или добавлять
  реальную параллельность.
- Если схема `listings`/`seen_ids`/`search_config`/`worker_status`/
  `cross_session_claims` должна измениться не так, как описано в `SPEC.md`.
- Если требование задания допускает два прочтения, или объём работы
  вырос против плана.
- Перед визуальным редизайном интерфейса — отдельный шаг, не мешать с
  правкой логики в одном промпте/коммите.
- Если предлагается добавить новую зависимость.

## Что проверить перед финальным ответом

- Прогнать `python3 -m pytest -v` и показать вывод целиком, включая падения.
- Запустить проект и показать, что он поднялся (для веб-режима — обе
  сессии, `?session=1` и `?session=2`).
- Проверить основной сценарий и один нештатный.
- Показать `git status`/`git diff --stat`, убедиться, что не тронуто
  лишнее.

Фраза «всё работает» без вывода команды ответом не считается.

## Соглашения проекта

Комментарии, логи и уведомления — на русском, в стиле уже существующего
кода (см. `notify.py`: эмодзи 🆕/💰 + короткий текст). Новые файлы
называются по аналогии с существующими (`db.py`, `worker.py` — по модулю
ответственности, не по фиче). ID объявления — regexp из URL (`_extract_id`
в `scraper.py`).
