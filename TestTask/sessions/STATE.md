**Обновлено:** 2026-08-28, сессия 1

## Готово

- Фича «две поисковые сессии» веб-режима `avito_parser`: session_id ∈
  {1, 2}, чередование в одном потоке (без параллельного скрапинга),
  кросс-сессионный дедуп на 24 часа (только для релевантных объявлений),
  атомарная миграция существующей БД на новую схему.
- Полный цикл задания пройден: контекст (`AGENTS.md`) → спецификация
  (`SPEC.md`) → наивный прогон (отдельная ветка/worktree, для сравнения)
  → реализация по спеке через `subagent-driven-development` (5 задач,
  каждая с ревью + при находках — фикс-раундом) → финальное ревью всей
  ветки (Opus) → фикс-раунд по его находкам → повторное ревью (чисто).
- Тесты: 74/74 проходят (`python3 -m pytest -v`).
- Ручная проверка: живой запуск `python app.py`, две независимые
  сессии подтверждены визуально (скриншоты в `sessions/screenshots/`)
  и через API (curl), пауза одной сессии не блокирует другую, `?session=`
  с некорректным значением → 400.
- Ветка смержена локально в `master`, без пуша.

## Не начато

- Визуальный редизайн интерфейса — сознательно вынесен за рамки этого
  цикла (см. `SPEC.md`, «Чего точно не делаем»); следующий логичный шаг,
  отдельным промптом, со скиллом `frontend-design` и компонентами
  21st.dev.
- Живая проверка миграции БД на реальном файле пользователя с историей
  (не на синтетических данных) — файла `avito_monitor_web.db` от
  прошлых запусков в репозитории не нашлось на момент проверки.

## Известные проблемы

- При единственной настроенной сессии до фикс-раунда финального ревью
  частота опроса Avito ошибочно падала вдвое — **починено**, но стоит
  помнить при следующей доработке `background_loop`: любая новая ветка
  условия там должна явно решить, короткий у неё wait (как у паузы/
  неготовой сессии) или полный интервал.
- Несколько Minor-находок ревью оставлены как есть осознанно (не
  блокируют функциональность) — полный список рулингов в
  `.superpowers/sdd/2026-08-28-two-search-sessions/progress.md`:
  голый `ROLLBACK` в `except BaseException` миграции без вложенной
  защиты; дублирование блока валидации `session_id` в 7 хендлерах
  `app.py`; `int(raw)` в `_parse_session_id` молча округляет дробные
  значения; неявный порядок колонок в `INSERT ... SELECT *` для
  `search_config`/`worker_status` внутри `_migrate_to_sessions`.
